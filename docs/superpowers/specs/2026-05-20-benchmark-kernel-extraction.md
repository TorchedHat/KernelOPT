# Lossless Kernel Extraction via TORCHINDUCTOR_BENCHMARK_KERNEL

## Problem

`build_standalone_kernel()` in `wrap_kernel.py` reverse-engineers Inductor's `kernel.run()` into `kernel[grid]()` calls. This translation is fundamentally lossy:

1. **Grid is always 1D** — but Inductor generates 2D/3D kernels. `tl.program_id(1)` returns 0 for all threads, so most output is never written.
2. **Buffer strides are dropped** — `empty_strided_cuda(shape, stride)` becomes `torch.empty(shape)`, breaking channels-last layouts.
3. **Constexpr values are hardcoded guesses** — `XBLOCK=1024, YBLOCK=8` instead of autotuned values.
4. **Grid variable selection is wrong** — divides `xnumel` by `YBLOCK` instead of `XBLOCK`.

This causes correctness failures on virtually all synthesized multi-dimensional kernels. KB L2 005 (ConvTranspose2d+bias+tanh) had 0% correctness pass rate because of this.

## Solution

Replace `build_standalone_kernel()` with per-kernel files generated by PyTorch's `TORCHINDUCTOR_BENCHMARK_KERNEL=1`. These files are self-contained, correct by construction, and use `kernel.run()` with the full Inductor runtime (grid computation, autotuning, stride preservation).

Tested and verified:
- KB L2 005 (Grid2D): all 5 benchmark kernel files run correctly, NCU profiles successfully
- KB L3 003 (Grid1D): all 4 benchmark kernel files run correctly
- KB L1 010 (no Triton — pure cuBLAS): no benchmark files generated, handled by fallback

## Design

### Synthesis Flow Change

**Before:**
```
torch.compile → output_code.py → wrap_inductor_output() (execution file)
                                → build_standalone_kernel() (LLM file — BROKEN)
```

**After:**
```
torch.compile (with TORCHINDUCTOR_BENCHMARK_KERNEL=1)
    → output_code.py → wrap_inductor_output() (execution file — unchanged)
    → per-kernel .py files in inductor cache → collect → clean for LLM
```

### File Changes

**1. `kernelopt/kernelopt/synthesis/compile_extract.py`**

Modify `_build_driver_script()` to set two env vars in the generated subprocess:
```python
os.environ["TORCHINDUCTOR_BENCHMARK_KERNEL"] = "1"
os.environ["TORCHINDUCTOR_UNIQUE_KERNEL_NAMES"] = "1"
```

Add a `TORCHINDUCTOR_CACHE_DIR` to a temp directory so we can find the generated files.

After `run_and_get_code()`, scan the cache directory for benchmark kernel files (files containing both `@triton.jit` and `def get_args` and `def call`). Return them in the result dict:

```python
results.append({
    "inductor_source": src,
    "triton_kernels": triton_kernels,        # existing — clean @triton.jit blocks
    "call_source": call_source,              # existing
    "benchmark_source": benchmark_source,    # existing
    "callable_info": info,                   # existing
    "benchmark_kernel_files": [              # NEW
        {"name": "triton_poi_fused_...", "source": source_text, "path": path},
        ...
    ],
})
```

The driver script collects benchmark files via `glob` and writes their paths + content to the output JSON.

**2. `kernelopt/kernelopt/synthesis/wrap_kernel.py`**

Keep `wrap_inductor_output()` unchanged — it produces the correct execution file for multi-kernel profiling.

Keep `_clean_for_llm()` unchanged — still used to clean kernel bodies for the LLM.

Add new function `build_benchmark_standalone()`:

```python
def build_benchmark_standalone(
    benchmark_source: str,
    original_pytorch_source: str,
) -> str:
    """Wrap a TORCHINDUCTOR_BENCHMARK_KERNEL file with kernelopt interface.

    The benchmark file already has correct kernel.run(), get_args(), and
    grid computation. We add:
    - _PYTORCH_REFERENCE (original source for context)
    - _TRITON_KERNEL_SOURCES (clean @triton.jit bodies for LLM reading)
    - kernel_function(*inputs) wrapper → delegates to call()
    - get_inputs() → delegates to get_args()
    - __main__ with --profile-only
    """
```

This is simpler than `build_standalone_kernel()` because we're not translating anything — just appending the kernelopt interface to an already-working file.

Remove `build_standalone_kernel()`, `_translate_call_to_kernel_function()`, `_build_standalone_wrapper()`, and `_CONSTEXPR_DEFAULTS` — all the lossy translation code.

Keep `_extract_get_inputs()`, `_extract_function_from_source()`, `_parse_kernel_signatures()`, `_extract_helper_functions()` — they're still used by `wrap_inductor_output()`.

**3. `kernelopt/kernelopt/langgraph_pipeline.py`**

In `maybe_synthesize()`, replace the `build_standalone_kernel()` call with:

```python
if primary.get("benchmark_kernel_files"):
    # Pick the benchmark file for the bottleneck kernel (by name matching or largest)
    benchmark_file = _select_bottleneck_benchmark(primary["benchmark_kernel_files"])
    standalone_kernel = build_benchmark_standalone(
        benchmark_source=benchmark_file["source"],
        original_pytorch_source=original_source,
    )
else:
    # Fallback: no Triton kernels (pure extern_kernels like cuBLAS mm)
    # Use the wrapped Inductor file as best_kernel
    standalone_kernel = wrapped_source
```

**4. Edge Case: No Triton Kernels**

When torch.compile produces only `extern_kernels` calls (e.g., KB L1 010 — pure cuBLAS matmul), no benchmark kernel files are generated. In this case:
- `best_kernel` falls back to `wrapped_source` (the full Inductor output)
- The planner sees the extern_kernels calls and the multi-kernel summary
- The strategy analyzer recognizes there are no optimizable Triton kernels
- The pipeline either skips optimization or proposes replacing the extern_kernel with a Triton implementation (Gap 3)

This is already handled by the existing strategy analysis logic.

## What Does NOT Change

- `wrap_inductor_output()` — still produces the wrapped file for multi-kernel profiling
- `_clean_for_llm()` — still cleans Inductor-specific APIs for the LLM
- The rest of the pipeline (planner, executor, profiler, correctness)
- CLI, state, checkpoint — no changes
- The layered defense (dry-run gate, API reference, profiling context) — all still work
